# GPU 迁移与独立仿真器

## 需要修改 SOFA 吗

本训练入口不需要。`gpu_core.py` 已经是 PyTorch 实现，读取预导出的几何与参数，在线物理步骤不调用 SOFA。SOFA 保留为离线对照模型。若未来决定在 SOFA 内新增材料／约束并训练，那属于另一条插件开发路线。

BeamAdapter 官方仓库包含 CUDA 扩展入口，但这不等于我们的自定义绳索、轮地接触和学习环境已自动支持 CUDA。参考：https://github.com/sofa-framework/BeamAdapter 。

## 将 SOFA 的核心拿出来可行吗

可行的范围是：保留所需梁理论、参考几何、质量与约束定义，建立专用张量实现，并逐项对照。当前已经走这条路线。原 BeamAdapter 源码、作者信息和 LGPL 许可在 `reference/BeamAdapter` 保留。

不能将“照着 SOFA 得到相同数值”视为模型准确。历史研究发现过接口和阻尼差异，必须区分：兼容原程序、修正已知问题、物理实验验证。代码路径一致不等于真实机器人一致。

## 这轮迁移范围

| 计算 | 原接口 | 新接口 |
|---|---|---|
| 刚柔物理和线性求解 | CUDA | CUDA，物理方程未替换 |
| Matsuoka／FOC | NumPy CPU | torch CUDA |
| 观测、延迟、噪声、历史 | NumPy／deque CPU | 固定形状 CUDA 张量 |
| 奖励、轮包络保护、回合重置 | CPU | CUDA 掩码运算 |
| PPO 网络、缓存、GAE、优化 | SB3 CPU | 原生 PyTorch CUDA |
| 初始化与读取拓扑 | CPU | CPU |
| 调度、检查点、日志、视频编码 | CPU | CPU |

每个 policy step 不使用 `.cpu()`、`.numpy()`、`.item()` 或依赖张量数值的 Python 条件分支。rollout 边界同步检查有效性、写日志、存模型。这不是整套程序被捕获成一张 CUDA Graph；Python 仍提交 kernel，物理子步使用已有 CUDA Graph。

## 验证与性能边界

- CPG：原 NumPy 与张量实现同初值同输入对照，c=0和0.75，各10秒。
- GAE：时间上限应 bootstrap，物理失败／成功终止不 bootstrap；任何重置不得把下一回合优势传播回上一回合。
- GPU 环境：三分支短时运行，检查观测与奖励驻留 GPU、有限数值、物理保护、单环境重置不改变同批其他环境。
- GPU 优化：真实环境观测经过网络和 Adam 更新；检查参数有限且发生更新。
- 每次训练保存真实吞吐与优化时间。没有独占硬件、同批量同任务的配对测量时，不宣称加速倍数。

新 PPO 与旧 SB3 不是位级复现：随机数生成器改为 torch，原生优化器路径及优势归一化细节不同，新版当前未启用 KL 早停。任务、执行器限制和奖励保持原试验定义。判断策略收益仍需同条件多种子训练与独立评估。

## 下一阶段验收

先完成单钢片、单体节、轮组、双体节和整机的力学检查，再增加统一残差迭代和实测标定。以新入口训练的模型必须单独评估；不能沿用旧模型的视频作为新策略效果。训练吞吐优化与物理可信度是两条独立验收线。
