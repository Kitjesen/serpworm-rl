## 状态与范围

已将 v1 的钢片梁、隔板惯性、绳索、舵机负载、节间连接、轮地接触、矩阵装配、线性求解和状态积分迁移到 PyTorch/CUDA。运行设备为 RTX 5090，使用 float64。SOFA 保留为离线对照；GPU 物理步不调用 SOFA，不把状态传回 NumPy 求解。初始化读取几何、控制命令提交、诊断输出和渲染仍由 CPU 管理。
当前覆盖单体节、双体节、五体节，每体节8片钢片、每片16单元。五体节共610个刚体截面自由度块、3660个标量自由度。先批量消去各钢片内部节点，再解60维隔板 Schur 系统，最后回代钢片状态。全部求解在GPU上；CUDA Graph减少提交开销。
这不是 Sano 或神经代理模型；这是对 SOFA 修正矩形截面共旋转梁路径的数值迁移。下方迁移和运动基准采用固定控制；后续传感器PPO使用此GPU核心，结果在页面顶部单独列出。

## 钢片和绳索是否双向耦合

有，传递路径是：绳张力 → 隔板力/力矩 → 钢片变形 → 钢片端部恢复力 → 隔板运动 → 绳长/张力变化 → 舵机负载。钢片端部与隔板使用共享自由度及安装偏置，力矩也参与装配。
绳索自由长度为 l0(theta)=0.101-delta(theta)。伸长为 e=l(q)-l0(theta)。当 e>=0 时，T=max(0,2000 e+0.5 dl/dt)，否则 T=0；这里 dl/dt 是端点相对速度在绳方向的投影。四根绳索对两隔板施加成对的力和偏心力矩。
舵机负载为同侧两绳张力之和乘收绳量对角度的导数。收绳角速度候选上限2 rad/s、扭矩上限0.5 N·m；负载接近上限时减速或停转。松绳仍是限速近似，尚未建立完整电机回驱模型。
因此不是把钢片恢复力直接当成绳张力；惯性、重力、接触和节间连接共同参与运动。现阶段耦合按小时间步推进，没有在同一次非线性 Newton 迭代中联立收敛，也未模拟绳与钢片表面直接接触。

## 为什么旧视频一震一震

原激励是诊断用目标切换。舵机按速度上限运动并在到达目标时突然停止；最大加速度出现在约0.898 s，随后释放与关节切换也激发振动。五次平滑指令 h(u)=10u³−15u⁴+6u⁵使目标角度、角速度与角加速度在过渡端点连续。只修改控制输入，没有平滑机器人位姿或视频。
在相同的旧滚阻、已修正质量阻尼条件下，500 Hz采样得到：

| 指令与步长 | 平移加速度分量RMS m/s² | 最大隔板加速度模长 m/s² |
|---|---:|---:|
| 5_h250_step_corrected | 0.4509 | 12.4299 |
| 5_h250_smooth_corrected | 0.0976 | 1.8791 |
| 5_h125_smooth_corrected | 0.1008 | 1.8340 |

这是同条件控制输入干预实验。以上峰值来自500 Hz记录，不声称捕获全部积分子步极值。25 fps视频也不足以表达高频振动，判断以时程数据为准。图见 vibration_comparison.png。

## 真正发现并修正的轮模型问题

单轮法向载荷1.4 N，滚阻参数0.06，等效启动阻力0.084 N。施加0.04 N推力，旧模型在0.25 ms时间步下仍以2.22 mm/s蠕滑；时间步减半后变成1.11 mm/s。原因是滚阻只根据上一时刻角动量限幅，零速时没有抵抗新施加驱动力矩。
当前把滚阻力矩与轮速联立求解，保留只允许单向转动的约束。修正后静止承载，接触弹性位移为0.02 mm；超阈值滚动、止逆、摩擦超载打滑、自由减速在三个时间步均通过单轮检查。摩擦系数与滚阻数值未被调小。
整机相同平滑指令、2秒回弹观察的时间步对照：

| 轮模型 | 间距RMSE mm | 间距最大差 mm | 前进位移最大差 mm |
|---|---:|---:|---:|
| 旧滚阻 | 0.09083 | 0.28353 | 1.74071 |
| 修正滚阻 | 0.00202 | 0.00616 | 0.00850 |

**回弹设计门槛仍未通过。** 修正滚阻后，第一体节在两种时间步下的残余压缩分别约2.711与2.708 mm，均超过原2 mm门槛。数值一致性改善了，但这不等于机器人已满足回弹要求。原先靠人为蠕滑减小残差的现象不能当作物理优势。
末期隔板最大速度约0.09–0.13 mm/s，仍有钢片恢复力和轮地阻力。结果提示受阻恢复，但没有经过实物轮机构/滚阻/钢片标定，不能认定真实机器人也会残留相同形变。下一步应测轮子的推拉启动阈值与回拉机构，结合自然预弯/装配预载核对恢复力；不能调摩擦来凑速度排名或通过门槛。

## 文件与复现

- gpu_core.py：当前GPU核心；source快照文件保留历史实现以匹配报告哈希。
- wheel_stiction.py：新旧单轮模型与五类验收实验。
- inputs/：冻结几何、材料参数、SOFA单步/矩阵对照输入。
- validate_kernels.py：SOFA兼容性、修正模型CPU/GPU一致性。
- run_gpu.py：单体节到五体节完整诊断；默认使用修正阻尼和滚阻。
- bench_and_coupling.py、bench_cpu.py：计时与钢片刚度干预实验。
- results/：全部成功和失败的报告、50 Hz完整状态与500 Hz诊断数据。
- render_cuda.py：只渲染保存状态；未通过验收的工况必须显式使用 --diagnostic，视频旁JSON记录失败状态。
- 当前五体节视频：5_h250_smooth_corrected_recovery2000_rrimplicit_1x.mp4。无字、1倍速，6.6秒；回弹门槛未通过，属于诊断演示。

运行环境需已有CUDA版PyTorch、NumPy；GPU主循环不需要SOFA。SOFA只用于export_reference.py和bench_cpu.py。常用命令：

```bash
python validate_kernels.py
python wheel_stiction.py
python run_gpu.py --count 5 --smooth --recovery 2
python run_gpu.py --count 5 --smooth --recovery 2 --dt 0.000125
python bench_and_coupling.py
```

输出目录已存在时拒绝覆盖，应保存到新的实验目录后运行。旧的单/双/五体节轨迹使用原核心快照；本轮最后的滚阻修正整机验收以五体节为主，单/双体节当前版本做了短程CPU/GPU一致性测试。
